# 2026-08-11 草稿试卷组卷

## 目标

试卷不再拥有独立题目内容，而是从一个对应题库选择题目；分值只存在于试卷与题目的组卷关系中。

## 实现

- 新增独立组卷 Repository 和可单测 HTTP handler。
- 管理员可查看试卷，为草稿绑定一个 active 题库，部分选题或全选 active 题。
- 已选题可稳定上下排序，可修改单题分值或将全部已选题设为统一分值。
- 分值修改后同一事务重算 `exams.total_score` 和 `round(total_score * pass_rate, 2)`，并递增试卷版本。
- 所有写请求要求题库管理权限、同源 JSON 和客户端版本号；事务内锁定试卷并写入审计日志。
- 只允许修改 `draft`；`scheduled`、`published`、`paused`、`closed` 和 `archived` 保持只读。
- 管理员弹窗支持桌面双栏和手机单栏布局，并阻止未保存选题被静默丢失。

## 历史数据边界

本步骤不更新 `questions.score`、`submissions`、`submission_questions`、已交答卷快照、作答或成绩。跨题库和归档题会在写入前被拒绝。

## 验证

- 组卷 Repository、API 和 UI 聚焦测试：28 项通过。
- 完整 `npm run check`：160 项测试、语法检查和敏感信息扫描通过。
- 内置浏览器连接本机页面时卡住，已按用户要求立即终止；真实 PostgreSQL 和手机视觉验收尚未执行。

## 风险与回滚

- 应用代码依赖 `0007_exam_authoring_score_ownership`。生产部署前必须先执行 `pg_dump -Fc`，再迁移并确认成功。
- 生产可能存在跨题库或空试卷；它们保持未绑定或只读，不做静默修复。
- 还未实现已发布试卷复制为新草稿，不应绕过状态检查直接改卷。
- 回滚本步只需回退组卷 Repository、handler、server 路由、管理员 UI、测试和文档；本步无新数据库迁移。若同版本同时部署 `0007`，按其 down 迁移单独回滚。
