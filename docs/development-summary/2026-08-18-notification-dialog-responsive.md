# 通知任务弹窗自适应宽度修复

日期：2026-08-18

## 问题与根因

生产 Phase A 验收时，通知列表、Worker 关闭状态和原有 12 条待发送任务均正常，但通知弹窗需横向滚动才能查看全部内容。

外层 `.admin-dialog` 宽度最多为 720px，内层 `.notification-dialog .admin-dialog-shell` 却被设为最多 960px，内层比外层宽 240px，因此产生横向溢出。

## 修改内容

- 将最大 960px 且保留视口两侧 16px 的自适应宽度设置在外层 `.notification-dialog` 上。
- 内层 `.admin-dialog-shell` 改为跟随外层的 `width: 100%`，并允许内容正常收缩。
- 更新管理员页的 CSS 版本参数，避免生产浏览器继续使用旧样式缓存。
- 新增回归测试，防止再次将宽度设在内层而撑开弹窗。

## 影响边界

- 不修改通知 API、通知数据、Worker 配置、发送逻辑或数据库结构。
- `T12_NOTIFICATION_WORKER_ENABLED=false` 应继续保持；本次修复不得触发原有 12 条 pending 任务。
- 没有使用浏览器控制，生产桌面和手机展示交由用户手动验收。

## 验证与回滚

本地 `npm run check` 已通过：语法检查、319 项测试和敏感信息扫描全部成功；`git diff --check` 通过。生产验收要点是：桌面端无横向滚动条、窗口收窄后弹窗跟随收缩、文字自动换行、手机端标题/筛选/按钮不溢出。

本次无数据库迁移。若展示异常，回滚本次代码提交并重启服务即可，不需要恢复 PostgreSQL 备份。
