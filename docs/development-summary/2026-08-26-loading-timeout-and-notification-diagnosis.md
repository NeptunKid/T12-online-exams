# 2026-08-26 加载超时与通知状态诊断修复

## 背景

生产验收发现：管理员关闭子页面后重新进入，用户列表可能一直停留在“正在载入用户”，反向代理最终返回 524；通知页面的状态数字显示为 0；考生首页或考试接口可能长时间处于载入中。

## 本轮改动

- PostgreSQL 连接池增加单条语句超时 `DB_STATEMENT_TIMEOUT_MS`，默认 15 秒，允许范围 1 至 120 秒，避免异常查询无限占用请求。
- 管理员 API 增加浏览器端 15 秒超时；用户列表失败后显示可操作错误；关闭管理对话框时递增加载令牌，旧请求完成后不会写回新页面。
- 通知统计在接口尚未成功读取前显示“通知状态读取中”和 `--`，不再把读取失败误显示为 0；接口成功返回后按数据库真实状态统计。
- 考生端认证、工作台、试卷、答卷详情和交卷请求统一增加超时与 HTTP 状态提示；初始化失败时回到可见登录提示区，避免无限加载。
- 更新管理员、考生资源缓存版本，并补充静态回归测试。

## 生产边界

- 本轮没有数据库迁移、生产写入、外部平台调用或通知清理。
- 生产部署前仍需按 `docs/production-deployment-runbook.md` 创建新的 PostgreSQL `pg_dump -Fc`。
- 通知状态全为 0 不能仅凭界面判断原因。请在阿里云 Workbench 执行交接文档中的只读 SQL，确认 `notifications` 表是否仍有历史任务，以及服务日志是否出现查询超时。
