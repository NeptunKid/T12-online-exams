# Phase 1：002 历史答卷备份与导入工具

日期：2026-08-07

## 任务与范围

建立 002 JSON 答卷的只读校验、不可覆盖备份、题目快照生成和 PostgreSQL 幂等导入工具。本步骤只完成工具和 dry-run 验证；不会在本机或云端数据库执行真实导入。

## 变更

- `scripts/backup-submissions.js` 暴露可测试的备份函数，保留原有命令行用法。
- 新增 `scripts/import-legacy-submissions.js`，读取显式来源路径，校验答卷 ID、状态、时间和题库 ID，生成默认历史考试、用户、身份、角色、题目、快照与答卷记录。
- 导入 SQL 使用事务、保留原答卷 ID 和 legacy 字段，并以 `ON CONFLICT DO NOTHING` 保证重复执行不覆盖已有记录。
- 实际导入前强制指定 `--backup-dir`，先创建带 SHA-256 的独立来源备份。

## 数据安全与兼容性

不会修改 `$HOME/Documents/Codex/002_考试后台追踪系统_钉钉登录版/data/submissions.json`，不把答卷内容、身份值或 `.env` 凭证写入 Git。题目完整快照写入 `submission_questions.snapshot_json`，历史成绩不依赖后续题库编辑。

## 验证

- `npm run check`：通过，13 项测试通过，含备份拒绝覆盖、旧字段兼容、schema、评分/权限和敏感信息扫描。
- 002 来源 `--dry-run`：通过，统计 2 条答卷、2 条已阅卷、36 道题、1 名历史考生；首题缺少旧题目 ID，已按来源字段稳定映射。
- 临时 PostgreSQL 端到端导入：通过，导入后为 2 条答卷、72 条逐题快照、36 道题、1 名用户、1 个身份；第二次导入记录数不增加。
- 已在 003 的 Git 忽略目录创建实际 002 来源备份及 SHA-256 校验文件；未修改 002 原文件，备份未提交 Git。

## 风险与回滚

真实云端导入需要在 Workbench 执行，且必须先确认 PostgreSQL schema 迁移已完成。导入事务失败会整体回滚；已生成的来源备份保留，停止新服务后可回到旧版本，不能删除 002 原文件。
