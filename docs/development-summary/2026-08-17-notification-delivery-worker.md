# 飞书通知发送、重试与人工重发

日期：2026-08-17

## 需求范围

继续 Phase 5 通知闭环：消费既有 Outbox 任务，完成飞书应用消息发送、多实例安全领取、失败重试、送达回执和系统管理员人工重发。钉钉发送权限和 Agent/机器人配置尚未确认，本步骤不猜测接入方式，也不领取钉钉任务。

## 修改内容

- 新增可回滚 `0011_notification_delivery_receipts`，只为 `notifications` 增加 `receipt_json` 和 processing 恢复索引；存在送达回执时 down 主动拒绝。
- Worker 默认关闭，只领取环境变量明确允许的 `feishu` 任务。
- 使用 `FOR UPDATE SKIP LOCKED` 防止多实例重复发送；超时 processing 自动恢复。
- 失败任务按指数退避，达到最大次数进入 `abandoned`；单任务失败不阻断同批其他任务。
- 飞书 transport 获取 tenant access token，以 `open_id` 发送文本应用消息并保存受控回执。
- 新增固定启用时间 `T12_NOTIFICATION_NOT_BEFORE`，早于该时间的历史 pending 不会突然补发。
- 系统管理员后台新增“通知”入口，可查看脱敏任务、Worker 状态和统计；仅已启用通道的 failed/abandoned 任务可人工重发，操作写入审计。
- API 和页面不返回真实收件人、消息正文、答案、解析、凭证或平台 Token。

## 部署与风险

- 本步骤尚未推送、合并或部署生产。
- 部署必须先创建 `pg_dump -Fc`，执行 `0011`，并保持 `T12_NOTIFICATION_WORKER_ENABLED=false` 完成后台列表验收。
- 只有在飞书开放平台确认应用消息/机器人发送权限后，才设置启用时间并打开 Worker。
- 当前钉钉任务继续保留为 pending，不能人工重发。
- 未使用浏览器控制技能；后台页面由用户部署后手动验收。

## 回滚

先关闭 Worker 并重启即可停止领取任务。代码可回滚到上一生产版本；若已产生送达回执，保留 `0011`，不要强制执行 down 或删除通知记录。
