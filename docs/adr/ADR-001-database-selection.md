# ADR-001：第一版数据库选择

日期：2026-08-06  
状态：已采纳

## 背景

003 需要从 JSON 答卷迁移到独立持久化存储，同时控制第一版云端部署成本。当前系统为单个 Node.js 服务，预计先以单实例运行。

## 决策

第一版在云端主机中使用 SQLite WAL：

- 数据文件路径由 `DB_PATH` 配置，默认 `data/exam.sqlite`。
- 数据库只允许本机应用进程访问，不开放数据库端口。
- 每日备份数据库文件和校验值到独立对象存储。
- 所有数据库访问通过仓储层实现，迁移文件保留可升级 PostgreSQL 的语义。

## 后果

SQLite WAL 降低了早期成本和运维复杂度，但不支持多应用实例共享写入。满足以下任一条件时，应迁移到托管 PostgreSQL：需要横向扩容、出现持续写入锁竞争、需要只读副本，或通知 worker 需要独立多进程高频写入。

## 备选方案

- 托管 PostgreSQL：更适合多实例和高并发，但第一版成本与运维配置更高。
- 保留 JSON：不满足事务、迁移、审计和多考试模型要求，拒绝采用。

## 修订：2026-08-06 PostgreSQL 云端部署

原 SQLite WAL 决策已被本修订取代。第一版改为在阿里云香港轻量应用服务器内运行 PostgreSQL 17：

- PostgreSQL 与 Node.js 位于同一云端主机，数据库只监听 `127.0.0.1:5432`，不开放公网端口。
- 使用独立数据库 `t12_exams` 和最小权限应用账户 `t12_app`。
- 数据库密码只存在部署 `.env` 或 Secret；Git 和日志不保存真实值。
- 每日执行 `pg_dump` 并将备份和校验值上传到独立对象存储。
- 后续若应用扩展为多实例，再迁移为同地域托管 PostgreSQL，不改变领域模型或迁移脚本语义。
