# 同类应用开发手册

本手册总结 T12 在线考试系统迭代中的工程原则、生产经验和协作方式，适用于其他需要接入企业平台、管理业务数据并持续部署的 Node.js 应用。

## 1. 先建立边界

- 先读项目记忆、交接文档、详细计划和来源项目交接文档，再动代码。
- 明确稳定版、来源基线、当前工作区和生产环境的边界；未经授权不修改来源目录，不共用答卷、数据库或上传资源。
- 每次只推进一个可验证、可回滚的步骤。跨模块需求拆成数据、服务、界面、测试和部署几个独立步骤。
- 外部凭证只放环境变量或部署 Secret。不要在源码、文档、日志、截图或提交信息中出现真实凭证、人员身份标识或答卷内容。

## 2. 需求到实现

1. 先复现并记录用户看到的现象、时间、请求路径、HTTP 状态和影响范围。
2. 区分前端兜底提示、反向代理错误、应用业务错误、第三方 API 错误和数据库错误；不要根据“请求失败”直接猜原因。
3. 优先使用现有模块、仓储、迁移和测试模式，避免无必要重写单文件服务。
4. 有持久化写入时使用事务、乐观锁、审计日志和幂等键；历史答卷、快照和成绩必须不可被后续题库编辑静默改变。
5. 删除优先采用软删除/归档；永久删除必须检查有效引用并提供备份回滚路径。

## 3. 第三方平台集成

- 将 OAuth、通讯录、消息发送拆成独立适配器，并用 provider + 外部身份 ID 建立稳定映射。
- 对每个接口记录请求方法、参数名、ID 类型、分页方式和返回字段；平台常同时返回 `id`、`department_id`、`open_department_id` 等字段，解析应兼容已确认的版本差异。
- 外部错误必须保留平台错误码和安全的短消息，隐藏 token、secret、完整 URL 和人员隐私；前端不能只显示不可诊断的“请求失败”。
- 空目录不能默认为成功，应提示权限、可见范围或组织确实为空，并避免因部门接口为空而跳过全量用户接口。
- 同步任务应具备分页、去重、重试/超时策略、事务写入和审计统计；缺失成员的停用策略要单独设计，不能一次同步就误停用全员。

## 4. 数据库与备份

- 每个 schema 变化都新增可回滚迁移；迁移必须可重复执行，生产执行前先 `pg_dump -Fc`。
- 备份文件记录绝对路径、大小和 SHA-256；备份目录权限按服务账号隔离，不能用错误用户运行 Git/npm。
- 导入导出使用带版本、整体校验和资源校验的自包含格式；图片等资源放入包内并逐一校验 MIME、魔数、大小和 SHA-256。
- 恢复或身份合并前先停止相关写入，并在隔离数据库验证备份；不要直接手改历史答卷或级联删除业务数据。

## 5. 测试与质量门

- 每个 bug 都加入最小回归测试；接口测试覆盖权限、同源校验、错误状态和事务回滚，纯函数测试覆盖边界值。
- 提交前至少运行：`npm test`、`npm run check:syntax`、`npm run check:secrets`、`git diff --check`。
- 不依赖浏览器自动验收作为唯一证据。无法稳定使用浏览器工具时，交给用户在真实电脑/手机执行明确步骤，并保留预期结果。
- 任何生产部署前都要确认当前 SHA、备份 SHA、迁移状态、`/readyz`、公网 `/healthz` 和服务状态。

## 6. Git、PR 与部署

- 使用 `codex/`、`feature/` 或 `fix/` 分支，禁止直接改 `main`；提交信息说明行为变化。
- 优先用命令行自动创建 PR：`git push` 后使用 `gh pr create --base main --head <branch> --title ... --body-file ...`。
- 网络操作容易卡顿时不要反复重试；把 GitHub 外部操作交给用户本机终端，开发侧只提供最短、带执行位置的命令。
- PR 合并后在阿里云 Workbench 统一执行：确认版本 -> 创建 PostgreSQL 备份 -> 以 `codexdeploy` 拉取和安装 -> 迁移 -> 重启 -> 健康检查 -> 用户验收。
- 回滚按风险选择：纯代码问题回退提交；已发生数据库写入则保留备份并先隔离验证，不能只回滚代码。

## 7. 与项目负责人的协作约定

- 用户希望先看到完整 Plan，再开始并发执行；复杂任务先说明 Agent 数量、角色和交付边界。
- 每条命令必须标注执行位置：本机终端、阿里云 Workbench、GitHub 页面或 Feishu，并说明预期输出。
- 用户亲自完成生产部署和真实验收；开发侧不使用浏览器控制技能替代用户验收，除非用户明确要求。
- 用户反馈“已提交/已合并/已部署”后，继续下一步，不重复要求已经完成的操作；需要 SHA、备份路径或日志时给出查询命令和示例输出。
- 遇到卡顿、网络断开或权限错误，立即暂停并说明阻塞点，不长时间等待；优先给可恢复的本地命令。

## 8. 每轮交付清单

- 修改文件和行为边界。
- 测试命令及通过数量。
- 数据库迁移、生产写入和外部 API 调用情况。
- 风险、回滚方式和未完成验收项。
- 文档、交接记录和后续命令。
